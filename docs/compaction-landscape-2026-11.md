# Compaction landscape audit — November 2026

**Recommendation:** improve final-output accounting and diagnostic preservation first. Then add bounded recovery and test session-local diagnostic deltas. Keep history compression and model-based summarization as separate experiments.

Audit window: **2026-08-16 through 2026-11-14**, UTC. Tokenjuice baseline: [`f647c3b`](https://github.com/vincentkoc/tokenjuice/commit/f647c3b393fae05c6640db51b2069049ba62c64b), version 0.11.0. Stars and upstream default-branch heads are November 14 snapshots; they can change.

## Scope and evidence

Screened **22 projects** across terminal-output reduction, structured-data encoding, prompt compression, recoverable context storage, and gateway/history compression. Selection combined GitHub discovery with direct competitors and original implementations. Stars establish visibility, not effectiveness. Smaller projects are included when they expose a particularly relevant technique or failure mode.

This is a source and release audit, not a comparative benchmark. Commit metadata, selected implementation diffs, tests, release notes, and current documentation were inspected. Full-window metadata coverage does **not** mean every changed line was reviewed. No upstream package was installed and no claimed savings or task-success result was independently reproduced.

Excluded model-weight/quantization and KV-cache libraries, multimodal token pruning, general long-term memory stores such as Mem0, and native agent compaction as standalone product audits. Those solve different layers. The gateway rows cover their relevant compression components, not their entire products. This is a bounded landscape, not a claim to enumerate every repository using the word “compression.”

## What tokenjuice already has

The shared [reducer](../src/core/reduce.ts) and [integration primitive](../src/core/integrations/compact-bash-result.ts) already provide deterministic command-aware transforms. [Inspection policy](../src/core/inventory-safety.ts) protects exact reads; [artifacts](../src/core/artifacts.ts) support opt-in originals; [JSON compaction](../src/core/reduce-utils.ts) preserves numeric source text while removing whitespace. Native adapter tests and the [verification inventory](verification-inventory.md) already distinguish installed configuration from model-visible behavior. These are strengths to extend, not features to rebuild.

The main gaps at this baseline are:

- **Accounting ends too early.** [Rewrite policy](../src/core/integrations/rewrite-policy.ts) compares reducer statistics, while [`decorateWrapInlineText`](../src/cli/main.ts) appends the authority footer and optional recovery instruction afterwards. Source inspection confirms the accounting boundary mismatch; its workload-level cost has not been measured here.
- **Character savings are not token or bill savings.** [Analysis](../src/core/analysis.ts) aggregates character counts. [Fixture benchmarks](../scripts/bench.mjs) measure timing and verification, not paired coding-task outcomes. [Codex-log analysis](../scripts/analyze-codex-logs.mjs) can summarize recorded tool token counts, but is not a causal before/after benchmark.
- **No general session-local output delta layer.** Adjacent-line dedup exists; cross-run diagnostic identity, explicit baseline invalidation and recovery debits do not form a shared product capability.
- **Generic JSON is minified/clipped, not schema-deduplicated.** The GitHub formatter is specialized; there is no general uniform-record encoding such as TOON.
- **Recovery semantics need stronger types before wider archival.** Compaction metadata records kinds and an `authoritative` flag, not a full distinction between format-only, omission, exact recoverability and unavailable originals. Current raw retention is deliberately optional.

## Ranked adaptation backlog

These are proposed follow-ups, not implemented changes or measured benefits. P0 means first engineering work; P1 is a bounded experiment; P2 is a separate product decision.

| Priority | Change | Why now / concrete acceptance gate |
| --- | --- | --- |
| **P0** | Account for the final emitted payload | Count headers, footers, recovery handles and later expansion. A small output must pass through if the entire replacement is larger. Preserve separate character, tokenizer and provider-usage measurements; negative net savings remain visible. |
| **P0** | Add host-aware replay and a small paired task benchmark | Replay only surfaces the actual adapter can replace. Separate automatic savings from optional tool use. Pin host/model/reducer versions; same command, output, repository state and warm-up in every arm. Measure task success, retries, latency and cache-class usage. |
| **P0** | Extend hard preservation and adversarial fixtures | Keep requested identifiers, error locations, exit status, exact file bytes and opaque provider metadata. A protected decision must survive every later stage. Test a unique diagnostic in the middle of a long successful-looking log. |
| **P1** | Make recovery capability explicit and bounded | A recovery marker requires a successful write and an available retrieval route. Test refused writes, short sensitive strings, stale IDs, cross-session isolation and capture truncation. Offer marker-free/pass-through behavior when recovery is unavailable. |
| **P1** | Pilot diagnostic deltas for one test/lint family | Always execute the command. Preserve new/changed diagnostics in full; distinguish explicitly passed from no longer observed. Key by session, cwd, command and tool identity; invalidate safely. Include all retrieval cost in the result. |
| **P1** | Trial exact structured-data encoding | Start with homogeneous JSON result arrays. Compare JSON minification, existing summary and TOON using real tokenizers plus retrieval tasks. Preserve IDs/numbers/nulls; avoid re-encoding exact file reads or API wire payloads. |
| **P1** | Check shell/worktree and upgrade contracts | Verify that pre-tool wrapping preserves host inspection and shell exit semantics. Exercise linked worktrees, compound commands, user-owned hooks and upgrades. Do not disable useful behavior globally based on one host's restriction. |
| **P2** | Evaluate retrieval/history compression separately | Require byte-stable cached prefixes, atomic tool exchanges and original provenance. Query-aware retrieval, model summaries and native compaction ownership materially expand the state and failure surface. |

## Recent changes worth studying

### Final payload and recovery accounting

Paritok's **Sep 10** fix found that a compression win disappeared after adding its reference tag. It now measures the tagged result before accepting or storing it. sqz's **Oct 23** fix likewise counts recovery-pointer overhead for small JSON. These directly motivate tokenjuice's P0 accounting change. Sources: [Paritok patch and regression](https://github.com/Paritok-official/paritok-4b-v1/commit/79274f4b9399c7793767cedb60fccc0d2d64ec72), [sqz pointer gate](https://github.com/ojuschugh1/sqz/commit/6d330f3340d1498ef7936f03a01d83b140e84554).

Token Optimizer's **Oct–Nov** corrections debit later recovery and distinguish pricing/baseline provenance. Token Optimizer MCP now documents gross transport reduction, expansion debit and net reduction as different quantities; its local tokenizer count is explicitly not an invoice. Adopt that separation without introducing billing estimates that guess an unknown model or route. Sources: [re-expansion correction](https://github.com/alexgreensh/token-optimizer/commit/783c4aef29d4858c329a9d18f3df1cddd4102e5b), [baseline correction](https://github.com/alexgreensh/token-optimizer/commit/aab9db4a2bbaf32ca866070061c17fb6f4961df7), [accounting contract](https://github.com/ooples/token-optimizer-mcp/blob/51b8f2cbc1206d6ad5c42bb1a21c21ceadaf63f1/docs/TOKEN_ACCOUNTING.md).

RTK corrected benchmark baselines on **Aug 31 and Nov 4**: compare actual classic diff output, precompile both arms, align color and excluded directories. tokf's **Aug 28** pipeline capture separates the first process's status from the shell pipeline's status and does not credit user-requested `tail` filtering as compressor savings. Sources: [RTK diff baseline](https://github.com/rtk-ai/rtk/commit/8495176c941f8e02df128320055547839ed0ab2a), [RTK benchmark repair](https://github.com/rtk-ai/rtk/commit/980ae9869c92d42f8905a086726a23eef29950a9), [tokf pipeline patch](https://github.com/mpecan/tokf/commit/7369dcf57875b6ccbedcefd15110967ca868adc6).

### Preserve the evidence the agent actually needs

Token Optimizer added **rare-token line retention Aug 27** to avoid discarding the searched-for identifier. Its heuristic keeps distinctive tokens occurring on at most two lines and backs off when too much output qualifies. Headroom added a **hard protection veto Sep 24**, followed by exact search-row/order preservation in November. A soft importance score is insufficient when an edit anchor or diagnostic must survive. Sources: [rare-token change](https://github.com/alexgreensh/token-optimizer/commit/221362fd9d98dec602803800c9b79bd4f494bae7), [hard veto](https://github.com/headroomlabs-ai/headroom/commit/d17ac6a174d9617951ca6eff4646da4c19f83922), [search preservation](https://github.com/headroomlabs-ai/headroom/commit/a538740ee40a80642bb1092d179171828260696c).

DCP's **Sep 16** change shares one protection predicate across compression, deduplication, sweeping and failed-tool pruning. A Code Mode batch is protected when any nested call requires it. Tokenjuice recently excluded OpenClaw JavaScript aliases; this is the same class of boundary to test across future stages. Source: [DCP protection patch](https://github.com/Tarquinen/opencode-dynamic-context-pruning/commit/bbc2e6d8b061afeaa63bd5a0776f0260a94c6f13).

OmniRoute disabled default lossy transforms **Sep 22**, then fixed a remaining default old-tool truncation path **Nov 3**. The lesson is to classify what a transform does rather than trust a label such as “safe.” A shorter deterministic summary still omits information. Sources: [default policy](https://github.com/cheaper-inference/OmniRoute/commit/2def447b15b48877426e70c991eced02ae097e5f), [remaining truncation fix](https://github.com/cheaper-inference/OmniRoute/commit/5a07ddd98e846b6d646744f216e137645294001b).

### Recovery before stronger compression

sqz fixed a storage bypass where **credential-shaped strings under 100 bytes** skipped sensitive-content detection; shipped in **v2.2.0 Nov 12**. squeez's **Sep 11** change returns original output when its recovery store refuses a write, rather than silently losing recoverability. Headroom's **Nov 8** marker-free mode disables transforms needing recall when the caller cannot retrieve. These are separate decisions: whether output may be transformed, whether it may be persisted, and whether the caller can recover it. Sources: [sqz fix](https://github.com/ojuschugh1/sqz/commit/fce492f02bf20f5ea564d3a29b25a711e1fbc536), [squeez fallback](https://github.com/claudioemmanuel/squeez/commit/97f02513850901789dc0a1d703b2cfcc0524a7cb), [Headroom capability mode](https://github.com/headroomlabs-ai/headroom/commit/33f067a243b2e648730c01ae6b9f20cba879f351).

Headroom's **Sep 24** markers began naming omitted error types/files. Context Mode's **Oct 23** retrieval change combines word and trigram search with rank fusion; its own evaluation reports recall@5 improving from 0.80 to 0.86, with higher p95 search latency. That supports measuring retrieval quality and cost together. It does not establish that tokenjuice needs a search database. Sources: [descriptive markers](https://github.com/headroomlabs-ai/headroom/commit/62d1cc08b10c3e397875d82a33e500ce9a6b44e7), [retrieval evaluation](https://github.com/mksglu/context-mode/commit/f8f7850e4bc8afcb662807d65dc741ed70660f36).

### Session-local deltas, with honest state boundaries

Token-Saver **v3.0.0 Sep 19** is the cleanest small experiment to borrow: opt-in deltas for pytest/Ruff, full new and changed failures, explicit pass versus disappearance, bounded local snapshots, and `delta show` recovery. Its benchmark includes retrieval cost. The command still executes; only presentation changes. Source: [implementation and fixtures](https://github.com/ppgranger/token-saver/commit/fd3c6dd2a545e08a6aaecfcff0e07ca29b1d2a05).

Token Optimizer introduced cross-turn dedup **Aug 27** and later added agent scoping, recency, hashes and write invalidation. billion-context's **Aug 31** fixes separate side/title requests from the main session and preserve originals across native compaction; its **Nov 14** watermark repair demonstrates how a memory optimization can silently disable a fast path. Any delta layer needs explicit invalidation and tests that prove its intended path actually runs. Sources: [dedup introduction](https://github.com/alexgreensh/token-optimizer/commit/f10fcb06562a4b20350c02a076ae7166e9c546ff), [write invalidation](https://github.com/alexgreensh/token-optimizer/commit/8f7cc2dd8fbec0429a84f7b52b29c9c807fdf42a), [side requests](https://github.com/ranxianglei/billion-context/commit/10c872a1f0496028d73a78825e378ab64e879b56), [watermark fix](https://github.com/ranxianglei/billion-context/commit/3728f968fddb987f006060afdf3d3e95b737f1b0).

### Structured JSON before semantic summarization

TOON's current v4 format shares repeated schema and supports nested field groups/keyed tables. **v4.4 Oct 8 changed conformance, not encoding syntax**: stricter malformed-input rejection, defined permissive recovery, sparse-array/null and BOM edge fixes. Its migration guide warns that old permissive decoders can silently misread new keyed tables. Tokenjuice should benchmark an opt-in exact representation on suitable result data, not invent a loosely similar syntax or apply it to exact source reads. Sources: [v4.4 release](https://github.com/toon-format/toon/releases/tag/v4.4.0), [migration and version distinctions](https://github.com/toon-format/toon/blob/22caca377f08d737789a2ca60ab02c425a3aa947/docs/guide/whats-new-in-v4.md).

Token Optimizer MCP's **Sep 23** JSON change chooses the smaller exact/lossy representation and has a separate numeric-source preservation fix. Tokenjuice already preserves numeric spelling during JSON whitespace removal; retain that property. LLMLingua and Selective Context offer no recent algorithm change that justifies introducing model inference into the default reducer. Sources: [encoding selection](https://github.com/ooples/token-optimizer-mcp/commit/e264f05e8c1926b0ce23adf751955547f5a8478e), [numeric preservation](https://github.com/ooples/token-optimizer-mcp/commit/d5a884d9e3c7), [tokenjuice implementation](../src/core/reduce-utils.ts).

### Cache and native-host contracts

Headroom currently replays already-forwarded prefixes byte-identically and compresses a live suffix; this is verified current behavior, not attributed wholesale to this window. LiteLLM's **Sep 15** fixes protect every message through the final cache breakpoint and inspect original structured content before normalization loses part-level flags. If tokenjuice adds history rewriting, protect tool call/result groups and cache prefixes as hard invariants. Its current one-shot output transforms do not own an entire conversation cache. Sources: [prefix tracker](https://github.com/headroomlabs-ai/headroom/blob/f2cdcedb085fc59ba16cf7135e257bc0d429648c/headroom/cache/prefix_tracker.py), [LiteLLM prefix fix](https://github.com/BerriAI/litellm/commit/9c59feee7cca3de0cb9727e9463cc5a3f66bf27b), [structured-marker fix](https://github.com/BerriAI/litellm/commit/931bdb8c0b50e825d249949b726bafd9f2825443).

Context Mode's **Nov 4–12** releases repeatedly repair native output fields, in-process replacement, reachable retrieval and hook upgrades. DCP v3.2.0 distinguishes V1/V2 behavior and unsupported permissions. tokf's **Sep 6** worktree guard addresses hosts that inspect a visible Git command before execution. Treat these as host-specific contract tests, not reasons to switch every host to one integration mechanism. Sources: [Context Mode v2.1.8](https://github.com/mksglu/context-mode/releases/tag/v2.1.8), [DCP v3.2.0](https://github.com/Tarquinen/opencode-dynamic-context-pruning/releases/tag/v3.2.0), [tokf worktree patch](https://github.com/mpecan/tokf/commit/32cb2377ec0bf9cfa9893b7931ee4059683fb0e1).

## Borrow ideas without importing the wrong product

RTK's **Oct 13** engine/proxy expansion is strategically relevant, but those directories use **BUSL-1.1**, while its CLI is Apache-2.0. Read the actual component grant before code reuse; independently implementing useful contracts avoids assuming that the CLI license covers the new engine. billion-context's kernel license includes an additional product-surface attribution condition. Do not copy tokf's default exit-code masking into tokenjuice. Do not enable cache keep-warm, model routing, or semantic summarization on the strength of an output-reduction percentage. DCP's [Sleev successor](https://sleev.ai) belongs on a watchlist: public implementation and independent performance were not established in this audit.

The recommended next work is three narrow changes: final-payload accounting, host-aware replay/quality fixtures, and recovery-capability metadata. Those create a trustworthy basis for deciding whether diagnostic deltas or structured JSON encoding actually improve tokenjuice.
